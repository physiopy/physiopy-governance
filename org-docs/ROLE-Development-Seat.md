# Developer Seat

The Steering Committee (SC) has two seats dedicated to software developement, the "Developer Seat" positions, as per our  [organisational charter](CHARTER.md) (see 3.3). In the absence of two volunteers, at least one seat should always be dedicated to software development.

When two developer seats are present, it is important that tasks are clearly allocated, and highlight which ones are essential and which are aspirational.

Essential tasks should cover maintenance and contribution monitoring, while aspirational tasks will likely reflect ideas about how to advance software development further, in accordance with the community requirements, interests, and available effort.

It is important that the Developer seats gain knowledge of the [Scientific Python Ecosystem Coordination](https://scientific-python.org/specs/), as well as having absolute understanding of Physiopy's [contribution guidelines](https://physiopy.github.io/contributors-guide/)  and development style.

## Current role definition 

Role definition designed by Stefano. New developer seats may want to edit/add aspirational tasks (A) when they onboard. The essential tasks (E) are likely to be more consistent across developer seats.

It is important to note that other community members, volunteers, SC and AB members can contribute to the tasks below - it is the developer seat's role to manage software contributions and ensure harmonic development above everything else. 

| Tasks                                                                                                                                                                                   | E/A |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- |
| Monitor codebase for necessary maintenance changes                                                                                                                                      | E   |
| Monitor new GitHub issues and assign urgency levels and contributions                                                                                                                   | E   |
| Take care of necessary and urgent updates to codebase and automations, refactoring code where necessary to keep libraries updated against at least one set of SPEC0 libraries versions. | E   |
| Manage and harmonise volunteers' efforts in software development                                                                                                                        | E   |
| Recruit volunteers for software development                                                                                                                                             | A   |
| Mentor volunteers on software development solutions for physiopy libraries                                                                                                              | A   |
| Proffer development solutions to the community                                                                                                                                          | A   |
| Offer suggestions on software development projects for hackathons                                                                                                                       | A   |
| Lead a software development project at hackathons                                                                                                                                       | A   |
